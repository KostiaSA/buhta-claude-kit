# 11. Генерация проводок (документ → проводки)

Этот документ описывает, **как БУХта автоматически формирует бухгалтерские проводки из документов**:
где хранятся настройки, как по ним генерируется хранимая SQL-процедура на каждый вид документа,
как эта процедура запускается по ключу документа, и какими ~50 «алгоритмами» вычисляется сумма
проводки. В конце — как всем этим управлять программно через HTTP-канал автоматизации
(`bmAutomationServer`, эндпоинты `POST /gen/*`).

> Источник: исходники `c:\bm` (Delphi 6, кодировка cp1251) и БД `NEMP_CLAUDE` (сервер `gold`).
> Номера строк в `*.pas` — ориентир на момент разбора, могут смещаться при правках.

---

## 1. Конвейер генерации (обзор)

```
┌─────────────┐   генератор текста        ┌──────────────────────────────────┐
│ [Генерация] │──────────────────────────▶│ CREATE/ALTER PROCEDURE           │
│ (настройки: │  StoredProcCreateGenDoc-  │ [dbo].[_авто_Документ_<Вид>_      │
│  правила    │  FromSpecSQL(Вид)         │        генерация]                 │
│  проводок)  │  + RefreshGenDocStoredProc└──────────────────────────────────┘
└─────────────┘                                        │ EXEC <proc> <КлючДок>
       ▲                                               ▼
       │ правка правил                        ┌──────────────────┐
       │ (UI TGenEditForm / automation)       │ GenDoc2Doc(Ключ) │─────▶ INSERT [Проводка]
       └──────────────────────────────────────┤ (bmGenDoc2Doc)   │
                                               └──────────────────┘
```

1. **Настройки** — строки таблицы `[Генерация]` (одна строка = одно правило: «из источника X сделать
   проводку Дт/Кт, сумма по алгоритму A»).
2. **Генерация процедуры** — по правилам вида документа строится текст хранимой процедуры
   `_авто_Документ_<Вид>_генерация` и создаётся/обновляется в БД.
3. **Запуск** — для конкретного документа вызывается `EXEC _авто_Документ_<Вид>_генерация <Ключ>`;
   результат — строки в таблице `[Проводка]`.

Ключевые юниты: `bmStoredProcGenDoc.pas` (генератор), `bmGenDoc2Doc.pas` (запуск),
`bmGenNastroikaForm.pas` / `bmGenEditForm.pas` (UI настройки).

## 2. Где хранятся настройки

### 2.1. Таблица `[Генерация]` — правила формирования проводок

PK — `[Ключ]` (int, identity). Одна строка = одно правило. В `NEMP_CLAUDE` — 65 видов документов
с настройками. Колонки (99 шт.) по группам:

| Группа | Колонки | Назначение |
|---|---|---|
| Идентификация / источник | `Ключ`, `Вид документа`, `Приоритет`, `Вид проводки`, `Операция`, `Источник вид докспец`, `Источник шифр з/п`, `Источник вид проводки` | к какому виду документа относится правило и что служит источником строк |
| Период действия | `Дата начала`, `Дата конца` | интервал применимости правила |
| Дебет / Кредит | `Дебет тип`, `Дебет`, `Кредит тип`, `Кредит` | счета проводки и способ их получения |
| Субконто Дт/Кт | `Дб субконто 1..5` (+ `… тип значения`, `… значение`), `Кр субконто 1..5` (аналогично) | аналитика по дебету и кредиту |
| Количество | `Дб количество`(+ `значение`), `Дб количество 2`, `Кр количество`, `Кр количество 2` | количественный учёт |
| **Сумма (алгоритмы)** | `Сумма`, `Сумма значение`, `Валюта`, `Сумма руб.`, `Сумма USD`, `Перевод суммы в другую валюту`, `Сумма курс`/`Сумма дата`, `Сумма руб. курс`/`… дата`, `Сумма USD курс`/`… дата`, `Входит в сумму` | **как считается сумма проводки** — см. §5 |
| FIFO-сортировки | `Дб FIFO 1..5 сортировка`, `Кр FIFO 1..5 сортировка` | порядок списания партий для FIFO-алгоритмов |
| Фильтр | `Фильтр`, `Фильтр включить` | ограничение строк-источников по именованному фильтру |
| Привязка (link) | `Привязка виды`, `Привязка тип субконто`, `Привязка номер субконто` | распределяющие алгоритмы (@SpecAll…) |
| Пользовательский SQL | `SQLDeclare`, `SQLBefore`, `SQLSelect`, `SQLJoin`, `SQLWhere`, `SQLAfter` (тип `text`) | ручные вставки в генерируемую процедуру |
| Прочее | `Примечание`, `Копировать примечание`, `Комплекты`, `Заполнять докспец`, `Группа`, `Конфигурация`, `Версия` | |
| Аудит | `Кто изменил`, `Когда изменил`, `Что изменил` | кто/когда правил правило |

Генератор читает правила тремя курсорами по типу источника (`bmStoredProcGenDoc.pas:~7259`):
- `[Источник вид докспец]>0` — источник строки спецификации (`FMainSourceType='Spec'`);
- `[Источник шифр з/п]>0` — источник строки расчёта зарплаты (`'Zarp'`);
- `[Источник вид проводки]>0` — источник существующей проводки (`'Prov'`).

### 2.2. Глобальные флаги — `[Настройка]`, секция «Генерация проводок»

- `Генерация с пустым корр.счетом` (ДаНет);
- `Генерация с разными контурами` (ДаНет).

## 3. Как создаётся SQL-процедура генерации

Ядро — `bmStoredProcGenDoc.pas`. Интерфейс:

```pascal
function StoredProcCreateGenDocFromSpecSQL(DocVid:Integer; ShowErrorDialog:Boolean=True):String; // :111
function StoredProcDeleteGenDocFromSpecSQL(DocVid:Integer):String;                                // :7932 (DROP)
procedure CreateGenDocStoredProc(DocVid:Integer);                                                 // :7944 (DROP+CREATE)
procedure RefreshGenDocStoredProc(DocVid:Integer; ShowErrorDialog:Boolean=True);                  // :7950 (ALTER|CREATE)
```

- **`StoredProcCreateGenDocFromSpecSQL`** собирает текст процедуры в `TStringList` (~7800 строк логики).
  Заголовок генерируемой процедуры:
  ```sql
  CREATE PROCEDURE _авто_Документ_<Вид>_генерация
    (@DocID Int, @UseTempSaldo TinyInt=0, @Konturs VARCHAR(1000)='')
  ```
  Тело: подготовка (`SQLDeclare`/`SQLBefore`), выборка строк-источников (докспец/зарплата/проводки),
  вычисление счетов (`SQLDebetKredit`), субконто (`SQLSubconto`), количеств (`SQLDbKrKol`), **суммы**
  (`SQLSumma`/`SQLSummaRub`/`SQLSummaUSD`, см. §5), затем INSERT в `[Проводка]`
  (`AddSaveProvodkaBody`, `:~7094`).
- **`RefreshGenDocStoredProc`** — рабочий вход: проверяет наличие процедуры в `sysobjects` и делает
  `ALTER PROCEDURE` (замена `CREATE`→`ALTER`) либо `CREATE`. `ShowErrorDialog=False` подавляет
  модальные диалоги (обязательно при вызове из automation).

**Кто вызывает создание процедуры (в UI):**
- `TGenEditForm.SaveData` (`bmGenEditForm.pas:~2113`) — после сохранения одного правила;
- `TGenNastroikaForm` (`bmGenNastroikaForm.pas`, кнопки Add/Edit/Copy/Delete) — после любой правки настроек;
- `bmDocVidEditForm.pas` — после правки вида документа;
- «Пересоздать все процедуры» — `bmDatabaseServiceForm.pas:~399` (цикл по всем видам).

**Просмотр текста процедуры в UI:** кнопка «показать SQL» в `TGenNastroikaForm`
(`UsersSQLButtonClick` → `StoredProcCreateGenDocFromSpecSQL`, показ в `TSQLForm`).
Текущий текст **в БД** — `sp_helptext` / `OBJECT_DEFINITION` / `sys.sql_modules`.

## 4. Как запускается генерация

Функция `GenDoc2Doc(RecordID:Integer)` (`bmGenDoc2Doc.pas:~726`):

```pascal
// SELECT Номер, Вид, Дата FROM Документ WHERE [Ключ]=RecordID   -- узнать вид документа
// EXEC _авто_Документ_<Вид>_генерация <RecordID>                -- сгенерировать проводки
// + INSERT в [История] (аудит запуска)
```

Тело простое, **без UI-диалогов** — поэтому безопасно вызывать из automation.

**Точки запуска в UI:**
- кнопка «Сгенерировать проводки» на форме документа (`TDocEditForm.GenButtonClick`,
  `bmDocEditForm.pas`); авто-вызов в `AfterSaveData`;
- массово из грида документов (`bmGrid.pas`, прогресс-бар «Генерация проводок»);
- диалог пере-генерации за период (`bmGenDoc2DocDialog.pas`).

**Хуки:** перед генерацией диспатчится событие `OnBeforeGenProv` (можно отменить); у вида документа
есть поле «Запустить после генерации» (пост-SQL). Результат генерации — строки в `[Проводка]`
(ссылка на документ — поле `[Документ]`; служебное поле `[ГенТип]`, ошибки — `[Ошибки генерации]`
в `[Документ]`).

### 5.8. Распределение / таможенная пошлина
В `SQLSumma` дают `[Докспец].[Сумма]`; реально распределяются процедурой `MakeRaspredSumma`
(`:~5540`); для пошлины сумма × `[Докспец].[Ставка таможенной пошлины]` (`:~5926`). Привязка —
поля `Привязка …` и переменные `@SpecAll…` (`LinkAlgoritm_GetVariableName`, `:~68`).
| Код | Смысл | Строка |
|---|---|---|
| `Распределение по сумме` | пропорц. сумме | 3402 |
| `Распределение по сумме без НДС` | как «по сумме», но числитель = `Сумма − Сумма НДС`, знаменатель = `SUM(Сумма)` (с НДС) | 3402 / 5888 |
| `Распределение по количеству` | пропорц. количеству | 3403 |
| `Распределение по количеству 2` | пропорц. количеству 2 | 3404 |
| `Распределение по весу нетто` | пропорц. нетто | 3405 |
| `Распределение по весу брутто` | пропорц. брутто | 3406 |
| `Таможенная пошлина по сумме` | сумма × ставка пошлины | 3407 / 5926 |
| `Распределение по сумме руб.` | (только в `SQLSummaRub`) | 3594 |
| `Распределение по сумме у.е.` | (только в `SQLSummaUSD`) | 3700 |

**`Распределение по сумме без НДС`** (вариант A) — штатная замена костыля, которым базу распределения
переопределяли вручную через `[SQLSelect]`/`[SQLAfter]` (`@SpecAllSumma_<вид>_<ключ>_One = Сумма − Сумма НДС`;
исходно — правило 1151, вид 29). Числитель (доля строки) считается без НДС (`GetSQLFormula` →
`[Докспец].[Сумма]-[Докспец].[Сумма НДС]`), а знаменатель и `@Summa` остаются **с НДС**
(`SUM([Докспец].[Сумма])`; `SQLSumma` → `[Докспец].[Сумма]`) — поэтому проводки совпадают бит-в-бит с прежним
костылём. Регистрируется в тех же 7 точках, что и `Распределение по сумме` (`IsLinkAlgoritmSource`,
`IsLinkAlgoritmSourceSumma`, `LinkAlgoritm_GetVariableName`, `SQLSumma`, `MakeRaspredSumma`, `GetSQLFormula`,
диспетчер), плюс пункт в `SummaEdit`/`SetLinkControlVisible` (`bmGenEditForm.pas`).

**Контроль полноты разброса** (только для этого алгоритма): перед докидкой остатка проверяется
`ABS(ROUND(_One − @DeltaSumma, 2)) > @RaspredCount · 0.01`; если расхождение больше копеечного округления —
генерация документа **падает** `RAISERROR(@RaspredErrorMsg, 16, 1)` + `RETURN` (после закрытия курсоров, до
переноса `#ГенПроводка → [Проводка]`, поэтому документ не создаётся). Новые переменные генерируемой процедуры:
`@RaspredCount` (счётчик целевых проводок строки-источника), `@RaspredError`/`@RaspredErrorMsg`. Проверка —
`bmStoredProcGenDoc.pas:~7070`, бросок — `:~7849`.

## 6. Работа через automation (эндпоинты `POST /gen/*`)

Реализация — `bmAutomationServer.pas` (класс-задание `TGenJob`, роутер `HandleGen`); все операции
маршалятся в главный VCL-поток. Клиент — `tools/buhta_client.py`. Тело/ответ — JSON в cp1251.

| Эндпоинт | Тело | Ответ | CLI |
|---|---|---|---|
| `POST /gen/doc-vids` | `{}` | `{ok,count,docvids:[{vid,name,rules,has_proc}]}` | `--gen-doc-vids` |
| `POST /gen/rules` | `{docvid}` | `{ok,docvid,count,rules:[{…}]}` | `--gen-rules <N>` |
| `POST /gen/rule/get` | `{key}` | `{ok,key,rule:{…все поля…}}` | `--gen-rule-get <K>` |
| `POST /gen/rule/set` | `{key,fields:{col:val,…}}` | `{ok,key,docvid,updated,rule:{…},sql:"…"}` | `--gen-rule-set <K> -f "Колонка=значение"` |
| `POST /gen/proc/sql` | `{docvid}` | `{ok,docvid,name,sql}` (генерируемый текст) | `--gen-proc-sql <N>` |
| `POST /gen/proc/db` | `{docvid}` | `{ok,docvid,name,exists,sql}` (текст из БД) | `--gen-proc-db <N>` |
| `POST /gen/proc/refresh` | `{docvid}` | `{ok,docvid,name,action:"created"\|"altered"}` | `--gen-proc-refresh <N>` |
| `POST /gen/proc/recreate` | `{docvid}` | `{ok,docvid,name,action:"recreated"}` (DROP+CREATE) | `--gen-proc-recreate <N>` |
| `POST /gen/run` | `{docid}` | `{ok,docid,docvid,provodki:<кол-во>}` | `--gen-run <K>` |
| `POST /gen/provodki` | `{docid}` | `{ok,docid,count,provodki:[{…}]}` | `--gen-provodki <K>` |

Примеры:
```bash
python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" --gen-doc-vids
python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" --gen-rules 1
python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" --gen-rule-get 218
python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" --gen-proc-sql 1   # -> tools\_gen_proc_1.sql
python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" --gen-proc-db 1    # -> tools\_gen_proc_1_db.sql
python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" --gen-rule-set 218 -f "Приоритет=5" -f "Сумма=Докспец.Сумма"
python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" --gen-proc-refresh 1
python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" --gen-run 12345
python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" --gen-provodki 12345
```

`--gen-rule-set`: значение типизируется на сервере по типу колонки (число можно слать строкой —
`'10.9'` ляжет в varchar-счёт, `'5'` в int/money); `-f "Колонка=@null"` пишет SQL `NULL`.

## 7. Границы и безопасность

- `/gen/run` и `/gen/rule/set` **пишут в БД**; `/gen/proc/refresh` (и авто-refresh внутри `rule/set`) —
  это **DDL** (`ALTER`/`CREATE PROCEDURE`). Работать только на **тестовой** копии (`NEMP_CLAUDE`);
  откат при поломке — восстановлением копии базы.
- `/gen/rule/set` — **только правка полей** существующего правила (по «белому списку»: нельзя менять
  `[Ключ]`, `[Вид документа]`, аудит-поля). Не создаёт и не удаляет правила. После UPDATE всегда
  проставляется аудит и **пересоздаётся процедура** вида (`RefreshGenDocStoredProc`).
- Генератор вызывается с `ShowErrorDialog=False` — предупреждения не всплывают модально, а попадают
  в ошибку/текст ответа.
- **Новый алгоритм суммы** (или исправление логики генерации) — это правка `bmStoredProcGenDoc.pas`
  в проекте `c:\bm`, требующая **пересборки .exe** в IDE Delphi 6 и последующего `/gen/proc/refresh`.
