# 09. Руководство по созданию и редактированию форм (dream)

Практическое руководство: как устроены пользовательские формы БУХты, какие бывают сценарии,
какие компоненты и функции использовать, как делать SQL-запросы, вызывать отчёты и экспорт,
и как **программно** добавить/изменить элемент формы через HTTP-канал `/form/*`.

> Базис: где хранятся формы, сжатие полей и эндпоинты `/form/*` — см. [08-формы-dream.md](08-формы-dream.md).
> Источник примеров — корпус последних изменённых форм БД `<база_клиента>` (зарплата) и
> `OILCITY_20260423_1905` (WMS, формы терминалов — §10) + исходники `c:\bm`.

---

## 1. Что такое форма

Форма = строка таблицы `[Форма]` (ключ `[Имя]`):
- `[ДФМ]` — визуальное описание (DFM-текст), **сжато** (читать/писать только через `/form/*`);
- `[Скрипт]` — логика на **DelphiScript** (движок dream), тоже сжато;
- `[Класс]` — поведение формы; `[Язык]` — обычно `DelphiScript`; `[Таблица]` — связанная таблица.

Классы форм:
| Класс | Назначение |
|---|---|
| `Form` | универсальный диалог/отчётная форма (корневой класс ДФМ — `TSimpleForm`) |
| `HotKeyForm` | форма-действие, вызывается по горячей клавише/из грида (корень `THotKeyForm`) |
| `EditForm` | карточка редактирования записи таблицы (`[Таблица]`) |
| `LookForm` | форма списка/просмотра таблицы |
| `LookupForm` | форма выбора значения (выпадающий справочник) |
| `Library` | библиотека общих функций, **без UI** (подключается к другим формам) |
| `PocketPCForm` | **форма терминала сбора данных (WMS)** — экран ТСД: сканер штрихкодов, крупные кнопки/клавиши (корень `TPocketPCForm`, см. §10) |

> Префиксы/варианты `*_disable`, `dis_*`, `disable_*`, `Disabled_*` у класса (напр. `HotKeyForm_disable`) —
> это **временно отключённые** формы (движок их не регистрирует как активные). Для правки — тот же `/form/*`.

## 2. Анатомия формы

**ДФМ** — дерево объектов; корневой объект = сама форма, его класс определяет имя класса в скрипте:
```
object SimpleForm: TSimpleForm   // корень: <Name>: <КлассФормы>
  Left = 376
  Top = 244
  Width = 560
  Height = 300
  Caption = #1055#1077...         // Cyrillic в DFM кодируется кодами #NNNN
  OnShow = bmFormShow             // событие формы -> процедура скрипта
  object OkButton: TbuhtaButton   // дочерний компонент
    Left = 227
    Top = 217
    Caption = #1042#1099...
    OnClick = FormOkButtonClick   // событие -> процедура скрипта
  end
  object FormPlacement: TbuhtaFormPlacement ... end
end                               // закрывающий end корня
```

**Скрипт** — глобальная секция `var`, вспомогательные функции и **обработчики событий**. Обработчик
объявляется с префиксом класса корневой формы:
```pascal
var
  TableLockNum : Integer;         // глобальные переменные формы

procedure TSimpleForm.bmFormShow(Sender: TObject);   // OnShow
begin
  // инициализация при показе
end;

procedure TSimpleForm.OkButtonClick(Sender: TObject); // OnClick кнопки
begin
  OkResult := True;               // у диалогов: результат
  Close;
end;
```

Правила:
- **Имя обработчика = `procedure T<КлассКорневойФормы>.<Имя>(Sender: TObject);`** (для `TSimpleForm` →
  `procedure TSimpleForm.X(Sender: TObject)`; для `THotKeyForm` → `procedure THotKeyForm.X(...)`).
  Кнопочный обработчик с кнопкой-эдитом бывает `(Sender: TObject; AbsoluteIndex: Integer)`.
- **Именованные компоненты доступны в скрипте по `Name`**: `NumEdit.Value`, `ResultLabel.Caption := '…'`,
  `OkButton.Enabled := False`.
- Событие показа формы почти всегда `OnShow = bmFormShow`. По соглашению есть и другие обработчики
  жизненного цикла: `bmFormBeforeShow` (до показа), `bmFormClose` (`OnClose` — финализация/проверки),
  `bmFormKeyDown` (`OnKeyDown` при `KeyPreview=True` — горячие клавиши). Объявляются так же:
  `procedure T<Класс>.bmFormClose(Sender: TObject; var Action: TCloseAction);` и т.п.
  У ТСД-форм (`TPocketPCForm`) добавляются `bmFormCreate` (`OnCreate`), `bmFormKeyPress`,
  и **`bmFormBarCodeRead`** (`OnBarCodeRead` — приход штрихкода со сканера, сам код в `bm.BarCode`).
  Гриды дают хуки `GridAfterLoad`, `GridSetViewFilters`, `GridBeforeCallEditForm` (события компонента грида).
- У диалогов результат возвращается через свойство формы `OkResult` (True/False) + `Close`.
- DelphiScript близок к Delphi: `begin/end`, `:=`, `if..then..else`, `while`, `for`, `var`,
  строки в апострофах, `+` для конкатенации. Регистр ключевых слов не важен.

## 4. Каталог скрипт-функций

Глобальные функции (регистрация: `c:\bm\import\bmVBInterface_imp.pas`, `bmMessage_imp.pas`,
`bmDreamFormVBInterface_imp.pas`). Вызываются из скрипта напрямую по имени.

### SQL и данные
| Функция | Назначение |
|---|---|
| `GetValueFromSQL(SQL): Variant` | **скаляр** из БД (самая частая функция). `GetValueFromSQL('SELECT COUNT(*) FROM [Сотрудник]')` |
| `ExecuteSQL(SQL)` | выполнить INSERT/UPDATE/DELETE |
| `GetStringListFromSQL(SQL): string` | список значений (через разделители) |
| `NewTable/NewView/NewQuery/NewStringList/NewParam` | фабрики объектов данных (`TbuhtaTable`/`TbuhtaView`/…) |

Также доступен глобальный объект **`bm`** (`TbmApp`): `bm.GetValueFromSQL`, `bm.ExecuteSQL`,
`bm.UserName`, `bm.UserID`, `bm.Kontora`, `bm.PodrID`.

### SQL-литералы (экранирование значений в SQL)
`StringAsSQL(s)`, `DateAsSQL(d)`, `DateTimeAsSQL(dt)`, `PeriodAsSQL(b,e)`, `IntegerAsSQL(i)`,
`CurrencyAsSQL(c)`, `BooleanAsSQL(b)`. Пример: `'… WHERE [Дата] >= ' + DateAsSQL(BegDate)`.

### Сообщения и подтверждения (`bmMessage_imp.pas`)
`bmInformation(msg)`, `bmWarning(msg)`, `bmError(msg)` (прерывает), `bmConfirmation(msg): Boolean`
(Да/Нет), `bmYesNoCancelMsg(msg)`.

### Запуск форм и отчётов
| Функция | Назначение |
|---|---|
| `ShowForm(name [,owner]): Boolean` | открыть другую форму по имени |
| `ShowModalForm(name [,owner])` | модально |
| `ShowReport(name [,owner])` | построить и показать отчёт (FastReport) по имени |
| `ShowReportWithParam(name, Param [,owner])` | отчёт с параметрами (`Param := NewParam`) |
| `PrintReport(name)` / `PrintReportWithParam(name,Param)` | печать без предпросмотра |
| `ShowArchiveReport(Self, ID)` | показать ранее сохранённый в архив отчёт по ID |
| `ShowEditForm(table, id, owner)` | открыть карточку записи таблицы |

### Глобальные переменные (передача параметров между формой и отчётом)
`SetGlobalVar(name, value)`, `GetGlobalVar(name): Variant`, `GlobalVarExists(name)`, `DeleteGlobalVar(name)`.
Частый паттерн: `SetGlobalVar('XL_Имя файла', True); ShowArchiveReport(Self, ReportId);`.

### Диалоги выбора
`DialogPeriod`, `DialogDate`, `DialogKadryID/DialogKadryList` (сотрудники), `DialogPodrID/List`
(подразделения), `DialogOrgID/List`, `DialogSQLID/DialogSQLList(SQL,...)` (выбор из произвольного SQL).

### Прочее
`VarToStr`, `VarToStrDef(v,default)`, `IntToStr`, `StrToIntDef`, `FormatCurr`, `Now/Year/Month/Day`, `Trim`, `Copy`, `Pos`,
`ReplaceStr`, `VBGetMoneyStr` (сумма прописью), `SetTableLock/ClearTableLock`, `CreateOleObject`.

### Дополнительные библиотеки (важно!)
Скриптам доступны **целые юниты Delphi**, зарегистрированные в `c:\bm\import\*_imp.pas` (каждый файл =
экспортированный модуль). Если нужной функции нет в списках выше — почти наверняка она есть в одной из
этих библиотек. Самые полезные:

- **Даты** (`bmDate_imp.pas`, `DATEUTIL_imp.pas`): `FirstDayOfMonth(d)`, `LastDayOfMonth(d)`,
  `FirstDayOfYear(d)`, `FirstDayOfQuarter/LastDayOfQuarter`, `FirstDayOfHalfYear/LastDayOfHalfYear`,
  `Quarter(d):Word`, `HalfYear(d)`, `DaysPerMonth(y,m)`, `StrToDateDef(s,def)`, `IsValidDateStr(s)`,
  `IsMonthPeriod/IsQuarterPeriod/IsYearPeriod/IsAllPeriod(b,e):Boolean`, `Date2SQL`. Очень удобно для
  логики периодов вместо ручного вычисления границ.
- **Строки** (`rxStrUtils_imp.pas`): `WordCount`, `ExtractWord`, `LeftStr/RightStr/CenterStr`,
  `DelChars/DelSpace/DelRSpace`, `ReplaceStr`, `Dec2Hex/Hex2Dec`, `IntToRoman/RomanToInt`,
  `ExtractDelimited`, `ExtractQuotedString`, `IsWild` (маска `*?`), `NPos`.
- **Утилиты/SQL/файлы** (`bmUtil_imp.pas`): `VariantAsSQL(v)` (SQL-литерал из Variant с учётом типа),
  `DateAsDBF(d)` (дата для DBF), `bmRound(c)`, `Boolean2String`, `CorrectFileName`, `CreateDirEx`,
  `ComputerName`, `DeleteLastChar`, `BmReadString/BmWriteString` (бинарные хранилища), семейство
  `*AsSQL/*AsJet` для всех типов.
- **Variants** (`Variants_imp.pas`): `VarToStrDef`, `VarIsNull`, `VarType`.
- **Стандартные** (`SYSUTILS_*`, `Classes_imp`, `Controls_imp`, `Dialogs_imp`, `ComObj_imp`,
  `DB_imp`, `ADODB_imp`, `Dbf_imp` — DBF-файлы): обычные функции Delphi (`Format`, `FloatToStr`,
  `StringReplace`, `TStringList`, файловый ввод-вывод `AssignFile/Reset/ReadLn/Eof/CloseFile`, COM).
- **Настройки/права** (`bmUtil_imp`, `bmaccess_imp`): `GetNastroykaValue(имя)` (значение настройки),
  `IsEmptyRef(v)` (пустая ссылка), функции прав доступа (`AccessRasdel`, `GetEnabledViews`…).
- **WMS / терминал ТСД** (`lgtcp_imp`): `PlaySoundOnPocketPC(тип)` (звук на терминале), команды
  сканера/связи; текущий штрихкод — `bm.BarCode`. См. §10.
- **Штрихкоды GS1 / маркировка «Честный знак»** (`bmGS1BarcodeUnit_imp`): класс парсинга GS1/DataMatrix —
  `Parse(код)`, доступ к application identifiers (`AI_ID/AI_Value/AI_List`, `TryGetValue`, `Count/Items`).

> Как проверить, что функция доступна: имя есть в списке строк `,'Имя'` в каком-либо `import\*_imp.pas`,
> **или** просто прогони `--form-check` со скриптом, который её вызывает.

### Методы компонентов (примеры)
`PeriodEdit.SetPeriodValue(dt)` (задать период), `Grid.IsRowSelected(node)` / `TreeList.IsRowSelected(node)`
(перебор отмеченных строк), `Edit.Value`, `Label.Caption`, `Button.Enabled/Visible`.

## 5. Классификация сценариев (с реальными скелетами)

### (a) Печатный отчёт / диалог параметров → отчёт  (класс `Form`, корень `TSimpleForm`)
Форма собирает параметры (период, шифры, флажки), по OK строит/показывает отчёт.
```pascal
procedure TSimpleForm.OkButtonClick(Sender: TObject);
begin
  if NumEdit.Value = '' then begin bmError('Заполните номер'); Exit; end;
  SetGlobalVar('XL_Имя файла', True);       // параметры -> глобалы
  ShowReport(ShablonNameEdit.Value);        // или ShowArchiveReport(Self, ReportId)
  Close;
end;
```
Образцы: «Печать Налоговой карточки НДФЛ-1 2023», «З/П Книга СВД-1».

### (b) Экспорт в XML для ГНИ/ПФР/СФР  (класс `Form`/`HotKeyForm`)
Строит XML через MSXML DOM; в каждой форме объявлены свои хелперы `SetOneNodeAttr`/`AddOneNodeText`.
```pascal
var XMLDoc, Root, Node1: Variant;
XMLDoc := CreateOleObject('MSXML.DOMDocument');
Root := XMLDoc.CreateElement('Файл'); XMLDoc.appendChild(Root);
Node1 := XMLDoc.CreateElement('Документ'); Root.appendChild(Node1);
SetOneNodeAttr(Node1, 'КНД', '1151111');        // атрибут
AddOneNodeText(Node1, 'Сумма', VarToStr(S));     // дочерний узел с текстом
FileStr := GetNextFile_XML(FileName, PathName);  // имя следующего файла
XMLDoc.save(FileStr);
```
Хелперы (копируются в скрипт формы):
```pascal
procedure SetOneNodeAttr(const tNode: IXMLDOMElement; tElement, tText: String; AddNullOk:Integer=0);
procedure AddOneNodeText(const tNode: IXMLDOMElement; tElement, tText: String);
```
Образцы: «Зарплата. Сведения по СЗВ 2015. Экспорт в XML», «Зарплата. Загрузка файла в эл.вид».

### (c) Экспорт/чтение Excel через COM
```pascal
var MyExcel: Variant;
GetReportAsOLEObject('Архив', ReportId, MyExcel);          // получить книгу из архива
s := VarToStr(MyExcel.Workbooks[1].Worksheets[1].Cells[12,69].Text);  // читать ячейку
// либо MyExcel := CreateOleObject('Excel.Application'); MyExcel.Workbooks.Open(path);
// сохранить заполненную книгу обратно в архив:
SaveFromOleObjectToArchive(MyExcel, 'Архив', RecID, RepName, Note, ArchNote, IsPersonal);
```

### (d) HotKeyForm-действие (ввод → валидация → ExecuteSQL)  (корень `THotKeyForm`)
```pascal
function OkInputData: Boolean;
begin
  Result := False;
  if VidEdit.Value = '' then begin bmInformation('Укажите вид'); Exit; end;
  Result := True;
end;

procedure THotKeyForm.FormOkButtonClick(Sender: TObject);
begin
  if not OkInputData then Exit;
  if not bmConfirmation('Создать документ?') then Exit;
  ExecuteSQL('INSERT [Документ] (...) VALUES (...)');
  OkResult := True; Close;
end;
```
Образцы: «Создание документа из книги продаж», «Зарплата. Регистр налогового учета в XML».

### (e) Library — общие функции без UI
Класс `Library`: только скрипт с функциями (XML-хелперы, расчёты), подключается к другим формам.
Образцы: «Зарплата. Загрузка файла в эл.вид (комп.формат)».

### (f) EditForm / LookForm / LookupForm
Привязаны к таблице (`[Таблица]`): карточка записи / список / выбор. Корневые классы — `TNewEditForm`/
`TLookForm`/`TLookupForm`. События данных `OnNewData/OnLoadData/OnSaveData`, поля `TbuhtaDBEdit` с `FieldName`.

### (g) Импорт из текстового файла
Чтение внешнего файла (выгрузки из банка/ПФР и т.п.) стандартным файловым вводом-выводом:
```pascal
var f: TextFile; line: string;
AssignFile(f, PathEdit.Value); Reset(f);
while not Eof(f) do begin ReadLn(f, line); /* разбор line, ExecuteSQL(...) */ end;
CloseFile(f);
```
Путь обычно из `TDirectoryEdit`/`TOpenDialog` (событие `OnChange`).

### (h) Экспорт в DBF
Для форматов ГНИ в DBF — компонент `TDbf` (модули `Dbf_imp.pas`) + `DateAsDBF(d)` для дат.
Поля/типы задаются программно, строки добавляются `Append`/`Post`.

### (и) Запрос к веб-сервису (ФНС и т.п.)
Проверка контрагентов/статусов через веб-сервис — SOAP-запрос по HTTP. Паттерн (COM, без зависимостей):
```pascal
var http, xmlSend: Variant;
http := CreateOleObject('Msxml2.ServerXMLHTTP.6.0');
http.Open('POST', 'http://npchk.nalog.ru/FNSNDSCAWS_2', 'false');
http.setRequestHeader('Content-Type', 'text/xml; charset=utf-8');
http.setRequestHeader('SOAPAction', 'NdsRequest2');
http.Send(xmlSend);                 // xmlSend — сформированный XML (см. §5б)
answer := http.responseText;        // разобрать ответ (LoadXML)
```
Образец: «Зарплата. Проверка контрагентов в WEB» (есть и вариант через компонент `TIdHTTP`).

### (к) WMS-форма терминала сбора данных (`PocketPCForm`)
Экран ТСД: ввод по сканеру, крупные кнопки, работа с паллетами/ячейками/маркировкой — см. §10.

## 6. Рецепты (cookbook)

**Скаляр из БД + сообщение:**
```pascal
bmInformation('Сотрудников в базе: ' + VarToStr(GetValueFromSQL('SELECT COUNT(*) FROM [Сотрудник]')));
```

**Подтверждение перед действием:**
```pascal
if bmConfirmation('Выполнить?') then ExecuteSQL('UPDATE ...');
```

**Чтение периода и подстановка в SQL:**
```pascal
n := GetValueFromSQL('SELECT COUNT(*) FROM [Документ] WHERE [Дата] BETWEEN '
     + DateAsSQL(PeriodEdit.BegDate) + ' AND ' + DateAsSQL(PeriodEdit.EndDate));
```

**Вызов отчёта по имени / с параметрами:**
```pascal
ShowReport('Имя отчёта');
// или:
Param := NewParam; Param.Value['Год'] := '2025'; ShowReportWithParam('Имя отчёта', Param);
```

**Добавить кнопку и обработчик** (ключевой рецепт):
1) В ДФМ вставить блок **перед закрывающим `end` корневого объекта**:
```
  object EmpCountButton: TbuhtaButton
    Left = 8
    Top = 238
    Width = 170
    Height = 25
    Anchors = [akLeft, akBottom]
    Caption = #1050#1086#1083'-'#1074#1086' '#1089#1086#1090#1088#1091#1076#1085#1080#1082#1086#1074
    TabOrder = 20
    OnClick = EmpCountButtonClick
  end
```
   (Caption можно задать и обычной строкой в апострофах — DFM принимает оба варианта;
   коды `#NNNN` — это юникод-символы кириллицы.)
2) В скрипт добавить обработчик (класс = корневой класс формы):

procedure TSimpleForm.EmpCountButtonClick(Sender: TObject);

## 7. Рабочий процесс правки формы (`/form/*`, без перезапуска .exe)

```bash
python tools/buhta_client.py --form-list --filter <подстрока>     # найти форму
python tools/buhta_client.py --form-get "<имя>"                  # dfm/script -> tools\_form_*.dfm/.pas (+ авто-бэкап при set)
# отредактировать локально tools\_form_<имя>.pas / .dfm
python tools/buhta_client.py --form-check "<имя>" --script tools\_form_<имя>.pas   # синтаксис ДО записи
python tools/buhta_client.py --form-set-script "<имя>" tools\_form_<имя>.pas       # записать [Скрипт]
python tools/buhta_client.py --form-set-dfm "<имя>" tools\_form_<имя>.dfm          # записать [ДФМ]
# открыть форму в .exe и проверить; при необходимости вернуть из tools\_form_<имя>_backup.*
```

Железные правила:
- **Проверять синтаксис (`--form-check`) до записи скрипта.**
- ДФМ/Скрипт — только через `/form/*` (поля сжаты; ручная правка в БД испортит данные).
- Правки идут в **БД запущенного .exe** (клиентская копия); эталон «Стандартная» — отдельно.
- Перед `set` автоматически делается бэкап `tools\_form_<имя>_backup.*` (откат — обратный `set`).
- Менять корневой класс формы в обработчиках нельзя — он фиксирован ДФМ-корнем.

## 8. Разбор примера

**Задача:** «найди форму печати НДФЛ за 2025, добавь внизу слева кнопку, показывающую сколько
всего сотрудников в базе».

1. `--form-list --filter НДФЛ` (или `--filter карточк`) → выбрать последнюю карточку НДФЛ.
   На текущей БД последняя — **«Печать Налоговой карточки НДФЛ-1 2023»** (формы «2025» нет → берём
   максимально свежую подходящую; если бы была «…2025», взяли бы её). Корень — `TSimpleForm`, 560×300.
2. `--form-get "Печать Налоговой карточки НДФЛ-1 2023"` → получить `dfm`/`script` (+ авто-бэкап).
3. В `dfm` вставить блок кнопки из §6 (Left=8, Top=238, `Anchors=[akLeft,akBottom]`) **перед последним
   `end`** (после объекта `FormPlacement`).
4. В `script` добавить `procedure TSimpleForm.EmpCountButtonClick(Sender: TObject)` из §6.
5. `--form-check … --script <файл>` → `valid=true`.
6. `--form-set-dfm` + `--form-set-script`. Открыть форму в .exe → кнопка «Кол-во сотрудников» внизу
   слева → нажать → «Сотрудников в базе: 927» (сверка: `q.py "SELECT COUNT(*) FROM [Сотрудник]"`).

> Статус проверки рецепта: см. раздел «Проверено» ниже — выполнен на живом .exe (edit+revert).

## 9. Проверено (живая валидация)

Рецепт §8 выполнен на живом .exe (БД `<база_клиента>`) методом edit+revert на форме
**«Печать Налоговой карточки НДФЛ-1 2023»** (корень `TSimpleForm`, 560×300):
- добавлена кнопка `EmpCountButton` (Left=8, Top=235, `Anchors=[akLeft,akBottom]`) и обработчик
  `procedure TSimpleForm.EmpCountButtonClick` со `SELECT COUNT(*) FROM [Сотрудник]`;
- `--form-check` → `valid=true`; после `set` форма открыта в .exe, кнопка показала
  **«Сотрудников в базе: 927»** (сверка `q.py` → 927) — **подтверждено пользователем**;
- форма возвращена в исходное состояние (кнопка/обработчик убраны, синтаксис валиден).

### ⚠️ Гочка с переводами строк (исправлено в клиенте)
Скрипты форм хранятся с `\r\n` (CRLF). При правке через файлы на Windows текстовый режим Python
(`open(...,'w'/'r')`) транслирует переводы строк и **удваивает** их (`\r\n`→`\r\n\r\n`), из-за чего
в редакторе появляются лишние пустые строки. Поэтому `buhta_client.py` открывает файлы ДФМ/скрипта
с **`newline=""`** (без трансляции) — байты концов строк сохраняются точно (проверено: round-trip
identical). Если правишь файлы другим инструментом — сохраняй CRLF и не давай редактору добавлять
пустые строки. Схлопнуть уже задвоенные: `script.replace('\r\n\r\n','\r\n')` до стабилизации.

## 10. WMS / формы терминалов сбора данных (`PocketPCForm`)

В конфигурациях со складским модулем (WMS) преобладают формы класса **`PocketPCForm`** — экраны
терминала сбора данных (ТСД/сканера): приёмка, размещение, отбор, инвентаризация. Корневой класс
ДФМ — `TPocketPCForm`. Отличия от обычных форм:

**Событие сканера.** Главный обработчик — `OnBarCodeRead`:
```pascal
procedure TPocketPCForm.bmFormBarCodeRead(Sender: TObject);
begin
  ProcessBarCode(bm.BarCode);   // отсканированный код — в bm.BarCode
end;
```
Сюда приходит результат скана; дальше код разбирают и выполняют шаг операции. Есть и
приложенческое событие `ApplicationOnBarCode` (глобальный перехват скана).

**Клавиши/звук терминала.** `bmFormKeyPress`/`bmFormKeyDown` (функц. клавиши, часто `IsP1Key/IsP2Key`),
`PlaySoundOnPocketPC(тип)` — звуковой сигнал успех/ошибка (`lgtcp_imp`). Иногда `keybd_event` (эмуляция клавиш).

**Разбор штрихкода маркировки (GS1 / «Честный знак»).** Библиотека `bmGS1BarcodeUnit_imp`: создать
парсер, `Parse(код)`, затем читать application identifiers (`TryGetValue`, `AI_Value`, `Count/Items`) —
GTIN, серийный номер, партия, срок. Для DataMatrix табачки/маркированных товаров.

**Доменные хелперы WMS** (`IsTMCFIFO`, `GetTMCType`, `IsTMCPart`, `IsHonestSign_TMC`, `GetPartFromPallete`,
`GetPalletaIDFromCell`, `IsEmptyPallet`, `AskPalMesto`, …) — это **не функции движка**, а процедуры из
**Library-формы WMS** (общая библиотека конфигурации), подключённой к терминальным формам. Перед
использованием в правке смотри их в соответствующей форме класса `Library` (через `--form-get`).

**Настройки/права.** `GetNastroykaValue('<имя настройки>')` — значение параметра WMS; `IsEmptyRef(v)` —
проверка пустой ссылки; функции прав (`bmaccess_imp`). Грид-формы используют хуки `GridAfterLoad`,
`GridSetViewFilters`, `GridBeforeCallEditForm`.

**Компоненты ТСД:** `TPocketPCForm`, крупные `TbuhtaButton`/`TbmButton`, `TShape`/`TImage` (индикация),
`TCheckListBox`, `TSplitter`. Координаты/размеры рассчитаны на маленький экран терминала.

> Правка терминальных форм — тем же каналом `/form/*`. Логику операции (что делать со сканом) почти
> всегда несёт скрипт формы + Library-форма WMS; визуал ДФМ обычно простой (поле ввода + кнопки + метки).
