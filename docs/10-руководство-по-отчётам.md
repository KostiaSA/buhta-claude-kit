# Руководство по печатным шаблонам БУХты ([Отчет]) — чтение, правка, печать

Печатные формы БУХты (накладные, счета-фактуры, книги покупок/продаж, декларации, ведомости,
балансы) хранятся в таблице БД `[Отчет]` и печатаются движком **FastReport** (а также встроенной
электронной таблицей / MS Excel / MS Word). Это руководство — как находить, читать, редактировать и
печатать такие шаблоны **снаружи**, через HTTP-канал `/report/*` в `bmAutomationServer`.

Родственные документы: формы dream — [docs/09](09-руководство-по-формам.md); устройство HTTP-канала и
сжатие полей — [docs/08](08-формы-dream.md); запросы/SchemaView — [docs/07](07-схема-данных-и-запросы.md).
Оперативный гид — skill **buhta-reports**.

> **Где правим.** Эндпоинты пишут в БД **запущенного .exe** (клиентская копия, напр.
> `<база_клиента>`). Эталон «Стандартная» не трогаем. Перед `set` клиент делает авто-бэкап.

## 1. Таблица `[Отчет]`

Ключ — **`[Ключ]`** (varchar 50, он же имя шаблона). Основные поля:

| Поле | Тип | Назначение |
|---|---|---|
| `[Ключ]` | varchar(50) | **PK / имя шаблона** |
| `[ТипШаблона]` | char(1) | тип движка (см. §2) |
| `[Группа]` | varchar(20) | категория (для группировки в дереве отчётов) |
| `[Примечание]` | varchar(50) | комментарий |
| `[Количество копий]` | int | копий при печати по умолчанию |
| `[Данные]` | image | **конфигурация наборов данных** (запросы + связи master-detail), VCLZip |
| `[Шаблон]` | image | тело FastReport 3/4 (VCLZip) |
| `[ШаблонExcel]` | image | тело встроенной электронной таблицы (**обычный текст** `BUHTA_OBJECT_LIST`) |
| `[ШаблонMSExcel]` | image | тело MS Excel (.xls, VCLZip) |
| `[ШаблонMSWord]` | image | тело MS Word (.doc, VCLZip) |
| `[Excel настройка печати]` | image | доп. параметры печати Excel |
| `[Кто изменил]` / `[Когда изменил]` / `[Что изменил]` | varchar(32)/datetime/varchar(1000) | **аудит** |

**Сжатие.** `[Данные]`, `[Шаблон]`, `[ШаблонMSExcel]`, `[ШаблонMSWord]` сжаты VCLZip: значение =
маркер **`Архив`** (5 символов cp1251, байты `C0 F0 F5 E8 E2`) + ZIP-архив с единственным файлом
`Q.Q`. Распаковка/упаковка — движковые `UnPackedReport` / `PackedReportStream`
(`c:\BM\bmReportUtil.pas`). `[ШаблонExcel]` (тип 1) — **не сжат**, читаемый текст. Эндпоинт `/report/get`
сам распаковывает и отдаёт тело/данные как **base64** (бинарь-безопасно).

Маршрутизация по типу — `MainPrepareReport`/`MainPrintReport`
(`c:\BM\bmReportTableLinkPrint.pas:1165`); загрузка тела по типу — `TReportEditForm.LoadData`
(`c:\BM\bmReportEditForm.pas:439`); запись — `SaveData` (там же, 619).

## 2. Типы шаблонов (`[ТипШаблона]`) и поле тела

| Тип | Движок | Поле тела | Формат тела | Правится как |
|---|---|---|---|---|
| `0` | **FastReport 3** | `[Шаблон]` | бинарный документ FR3 (.frf) | **только blob целиком** |
| `1` | Встроенная электронная таблица | `[ШаблонExcel]` | текст `BUHTA_OBJECT_LIST` | текст |
| `2` | **MS Excel** (OLE) | `[ШаблонMSExcel]` | .xls (бинарь) | только blob целиком |
| `3` | **MS Word** (OLE) | `[ШаблонMSWord]` | .doc (бинарь) | только blob целиком |
| `4` | **FastReport 4** | `[Шаблон]` | XML-подобный текст FR4 (.fr3) | **текст** |

> Маппинг сверен по `case` в `MainPrepareReport`/`LoadData` (не по догадкам). Запомни: **2 = MS Excel,
> 4 = FastReport 4** (легко перепутать). В типичной клиентской базе преобладает тип 0 (FR3).

`/report/get` возвращает `bodyKind` (`text`/`blob`) и `ext` (`.frf/.txt/.xls/.doc/.fr3`) — клиент
сохраняет тело в файл с нужным расширением. Для `bodyKind=text` (FR4-XML, встроенная таблица) файл
можно править в редакторе; для `blob` (FR3/Excel/Word) — заменять целиком (экспорт из дизайнера).

## 3. Рабочий процесс `/report/*` (инструменты tools/)

```bash
python tools/buhta_client.py --report-list [--filter ТОРГ] [--type 0] [--group "ТОРГ-12"]
python tools/buhta_client.py --report-get "<ключ>"        # тело -> tools\_report_<имя><ext>, данные -> .data
# править локально тело (для FR4/таблицы — текст; для FR3/Excel/Word — заменить файл целиком)
python tools/buhta_client.py --report-set-template "<ключ>" tools\_report_<имя>.fr3   # запись тела (авто-бэкап)
python tools/buhta_client.py --report-set-data "<ключ>" tools\_report_<имя>.data       # запись [Данные]
python tools/buhta_client.py --report-show  "<ключ>" [-p "имя=значение"]   # предпросмотр в .exe
python tools/buhta_client.py --report-print "<ключ>" [-p "имя=значение"]   # печать
# откат: --report-set-template "<ключ>" tools\_report_<имя>_backup<ext>
```

- Тело и `[Данные]` ходят **base64** (точные байты, без искажений). Файлы пишутся/читаются в
  **бинарном** режиме — проблемы с CRLF, как у форм, тут не возникает.
- Перед `set` авто-сохраняются `_report_<имя>_backup<ext>` и `.data`.
- Запись бинарь-безопасна: сервер кодирует значение в `0x..` varbinary-литерал (`StreamAsSQL`) и пишет
  `UPDATE [Отчет] ... + аудит [Кто/Когда/Что изменил]`. Перезапуск .exe не нужен (шаблон читается
  заново при каждой печати).

## 4. Структура `[Данные]` — наборы и master-detail

`[Данные]` — это сериализованное дерево (`TdxTreeList`) с **наборами данных** отчёта. Каждый узел —
набор: имя SchemaView-запроса (`ViewName`), а у дочерних узлов — поля связи с родителем
(`MasterFieldName`/`LinkFieldName`). Корневой узел (level 0) — **master** (например документ
`Документ`), дочерние (level 1) — **detail** (строки документа). Печать идёт бэндами FastReport: для
каждой записи master печатается секция, под ней — её detail-строки.

> `[Данные]` — **бинарный** поток (не XML/текст), поэтому правится только круговым переносом
> (`--report-get`→`--report-set-data` тем же файлом). Менять состав запросов удобнее в дизайнере
> отчётов БУХты; через канал — для бэкапа/переноса/массовой замены. Классы: `TbmBandDataSet`
> (`c:\BM\bmReport.pas:18`), чтение имён запросов — `UseViewInReport` (`bmReportUtil.pas:110`).

## 5. Печать

### По имени (`/report/show`, `/report/print`)
`ShowReport(name)` = `MainPrepareReport('VBScript', name, '', nil, nil)` — готовит и показывает
предпросмотр в запущенном .exe; `PrintReport` — печать (`MainPrintReport`). Из формы dream те же
функции вызываются как `ShowReport`/`PrintReport`/`ShowReportWithParam` (см. docs/09 §4).

Параметры передаются как `TParam` (пары имя=значение): `-p "Год=2025" -p "Период=..."`. В шаблоне
FastReport они доступны через `GETPARAM('Год')`; глобальные — через `SetGlobalVar`/`GETGLOBALVAR`.

```bash
python tools/buhta_client.py --report-show "Стандартный. Книга продаж 2026"
python tools/buhta_client.py --report-print "Товарная накладная ТОРГ-12" -p "Год=2026"
```

> Вызовы блокируют HTTP-ответ, пока окно предпросмотра/диалог печати открыто в .exe (клиент ждёт до
> 600 c). Это штатно — оператор видит результат и печатает.

### N экземпляров по документу (`/report/print-doc`)
Печать **привязанного к таблице** отчёта сразу по нескольким записям (например 100 накладных по 100
документам) — `ShowReportTableLinkPrint(TableName, Vid, RecordID, AOwner)`
(`bmReportTableLinkPrint.pas:375`): открывает диалог отчётов, связанных с таблицей `TableName`,
отфильтрованный по списку записей; оператор выбирает шаблон и печатает. Список ID master-набора задаёт,
сколько экземпляров напечатается (фильтр `PrintItems`/`ReportRecordIDFilter`, см. `SetupView`).

```bash
python tools/buhta_client.py --report-print-doc "Документ" --ids "1001,1002,1003" --vid 0
```

## 6. Разбор задачи: «напечатать N накладных по списку документов»

1. Найти шаблон: `--report-list --filter ТОРГ` → «Товарная накладная ТОРГ-12» (тип `0`, FR3,
   группа `ТОРГ-12`). Это master-detail отчёт по таблице документов.
2. Определить таблицу-источник документов и ID нужных записей (через `--report-get` глянуть `[Данные]`/
   ViewName, либо штатным запросом `buhta_client.py "<вид>"`).
3. Печать пачкой: `--report-print-doc "<таблица документов>" --ids "<id1,id2,...>"` → диалог печати,
   выбрать «Товарная накладная ТОРГ-12» → печатаются все указанные документы.
4. Альтернатива (один отчёт, параметры периода/фильтра): `--report-print "<ключ>" -p "..."`.

Правка самого шаблона (например добавить колонку):
1. `--report-get "Товарная накладная ТОРГ-12"` → тело `_report_*.frf` (FR3 — бинарь, целиком) или для
   FR4-шаблона `_report_*.fr3` (XML — правится текстом).
2. Заменить/отредактировать тело → `--report-set-template "<ключ>" <файл>` (авто-бэкап).
3. `--report-show "<ключ>"` → проверить вид → при необходимости откат из `_backup`.

## 7. Эндпоинты (справка)

| Метод | Тело | Ответ |
|---|---|---|
| `POST /report/list` | `{filter?,type?,group?}` | `{ok,count,reports:[{key,type,group,changed}]}` |
| `POST /report/get` | `{name}` | `{ok,name,type,group,note,copies,bodyField,bodyKind,ext,body(b64),data(b64),who,when,what}` |
| `POST /report/template/set` | `{name,body(b64),bodyKind?}` | `{ok,name,op,type}` |
| `POST /report/data/set` | `{name,data(b64)}` | `{ok,name,op,type}` |
| `POST /report/show` | `{name,params?}` | `{ok,name,op}` |
| `POST /report/print` | `{name,params?}` | `{ok,name,op}` |
| `POST /report/print-doc` | `{table,ids?,vid?}` | `{ok,table,op}` |

Ошибки: `{ok:false,error:..}` со статусом 400/404/500. Тело JSON — cp1251.

## 8. Железные правила

1. **Только через `/report/*`** — поля `[Данные]`/`[Шаблон]`/… сжаты VCLZip; ручная правка в БД испортит данные.
2. **Бэкап есть** — перед каждым `set` авто-сохранение `_backup`. Откат — повторный `set` бэкап-файлом.
3. **Правки в БД запущенного .exe**, эталон «Стандартная» не трогаем.
4. **Тело бинарных типов** (FR3/Excel/Word) — заменяется целиком; текстом правится только FR4-XML и встроенная таблица.
5. Файлы тела — **бинарные**, не редактируй их инструментами, меняющими байты/кодировку без нужды.
6. Тип шаблона: **2 = MS Excel, 4 = FastReport 4** (не перепутать).

## 9. Проверено

Сквозной тест на `<база_клиента>` (786 отчётов), 2026-06-07:

- **`--report-list`** — фильтры по ключу/типу/группе работают: `--filter ТОРГ` → 22; `--type 4` → 38
  (FR4); сортировка по `[Когда изменил]` DESC. Маппинг типов подтверждён на реальных данных
  (тип 0 FR3, тип 2 MS Excel, тип 4 FR4).
- **`--report-get`** — FR3 (тип 0): `bodyField=Шаблон`, `bodyKind=blob`, `ext=.frf`, тело ~33 КБ
  (распаковано из `Архив`+VCLZip). FR4 (тип 4): `bodyKind=text`, `ext=.fr3`, тело — **UTF-8 XML**
  (`<?xml version="1.0" encoding="utf-8"?><TfrxReport …>`), ~286 КБ — правится как текст.
- **Round-trip без потерь** на «Товарная накладная ТОРГ-12»: `get`→`set-template`/`set-data` тем же
  содержимым→`get`. MD5 распакованного тела совпал (`fdc90f20…`), MD5 `[Данные]` совпал (`8e3bec88…`).
  Аудит обновился: `[Кто изменил]=SA`, `[Когда изменил]`=текущее, `[Что изменил]=automation: set …`.
- **`--report-show`/`--report-print`** — несуществующий ключ → `404 report not found`. **Живой
  предпросмотр** «Стандартный. Список дебиторов и кредиторов» (тип 0): открыл окно FastReport в .exe,
  после закрытия эндпоинт вернул `{"ok":true,"op":"show"}`. Вызов через `MainPrepareReport`/
  `MainPrintReport` (как штатный `ShowReport`); ответ блокируется до закрытия окна (клиент ждёт до 600 c).
  `--report-print-doc` использует тот же движок (`ShowReportTableLinkPrint`).

> **Нюанс печати master-detail без контекста.** `--report-show "<накладная>"` без списка записей даёт
> «Нет данных для отчёта» (мастер-набор пуст). Для печати по конкретным документам — `--report-print-doc`
> с таблицей и `--ids` (или отчёт с параметрами периода через `-p`).

> **Кодировка тела.** FR4-шаблон хранится как UTF-8 XML; при текстовой правке сохраняй UTF-8.
> FR3/MS Excel/MS Word — бинарь, только замена целиком.
