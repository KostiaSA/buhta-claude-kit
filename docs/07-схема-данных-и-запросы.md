# 07. Схема данных и именованные запросы (SchemaView)

Этот документ описывает, **где БУХта хранит схему данных**, **что такое «запрос»**, как
запросы редактируются и выполняются в программе, и как получить результат — в том числе
программно (для HTTP-канала автоматизации `bmAutomationServer`, эндпоинт `POST /query`).

> Источник: исходники `c:\bm` (Delphi 6) и БД (таблицы `Schema*`). Кодировка исходников cp1251.

---

## 1. Где хранится схема данных (5 таблиц БД)

Вся схема — это **метаданные в самой БД** (а не хардкод в .exe). Программа читает их и на лету
строит SQL и формы.

| Таблица | Строк* | PK | Назначение |
|---|---|---|---|
| `SchemaTable` | 445 | `TableName` | таблицы (ключ, форма редактирования, вид/классификатор, автонумерация) |
| `SchemaTableField` | 7128 | (`TableName`,`FieldName`) | колонки таблиц (тип `DataType`, ссылка `ForeignTable`, выпадающие `ComboItems` и т.п.) |
| `SchemaView` | 1538 | `ViewName` | **запросы** (корневая таблица + фрагменты SQL + фильтры) |
| `SchemaViewField` | 34369 | (`ViewName`,`TableName`,`TableField`) | **поля запроса** (колонки SELECT, сортировка, формат, вычисляемые выражения) |
| `SchemaViewAlgoritm` | 1846 | `Ключ` | настройки оборотно‑сальдовых вычислений (Счёт/Субконто) для аналитических запросов |

\* кол-во строк в БД `Стандартная` (эталон конфигурации) на момент разбора.

### Реляционная модель (связи)
- `SchemaViewField.ViewName` → `SchemaView.ViewName`
- `SchemaViewField.TableName` → `SchemaTable.TableName`
- `SchemaViewAlgoritm.ViewName` → `SchemaView.ViewName` (а `ViewFieldName` → поле запроса)
- `SchemaTableField.TableName` → `SchemaTable.TableName`
- `SchemaTableField.ForeignTable` → `SchemaTable.TableName` (поля-ссылки, `DataType='Ссылка'`)
- `SchemaTable.VidTableName` → `SchemaTable.TableName` (таблица-классификатор «Вид …»)

### Ключевые колонки `SchemaView` (определение запроса)
- `RootTable` — корневая таблица (FROM).
- `SQLJoin`, `SQLWhere`, `SQLBefore`, `SQLAfter` — фрагменты SQL (джойны, фильтр, пре/пост‑SQL).
- `GroupingOk` — разрешена группировка.
- `UseKontoraFilter` / `KontoraFilterType` / `…Value` / `…Spisok` — фильтр по конторе.
- `Oborot` — признак оборотно‑сальдового запроса (тогда подключается `SchemaViewAlgoritm`).

### Ключевые колонки `SchemaViewField` (поля SELECT)
- `TableName`,`TableField` — источник поля; `Position` — порядок; `FieldName` — заголовок/алиас.
- `Sort` — сортировка; `Format` — формат числа/даты; `Footer` — агрегат в подвале; `Hidden` — скрыть.
- `SQLSelect` — **вычисляемое выражение** (если поле не прямая колонка таблицы).
- `Grouping` — режим группировки.

### Ключевые колонки `SchemaTableField` (колонки таблиц)
- `DataType` — доменный тип БУХты: `Целое`, `Строка`, `Деньги`, `ДаНет`, `Ссылка`, `Субконто`, …
- `DataSize` — размер; `ForeignTable` — таблица для ссылок; `ComboType`/`ComboItems` — выпадающий список (в т.ч. SQL).

## 2. Что такое «запрос» и как он редактируется

«Запрос» (view) в БУХте — это **именованная запись в `SchemaView`** + её поля в
`SchemaViewField` (+ при необходимости вычисления в `SchemaViewAlgoritm`). Имя запроса
часто (но не всегда) совпадает с именем таблицы (пример `Подразделение`).

Редактируется внутри программы визуальными редакторами (исходники-формы):
- `bmSchemaForm.pas` — редактор схемы (таблицы/поля/запросы);
- `bmReportEditForm.pas` — редактирование отчётов/запросов;
- `bmUsesrSQLForViewForm.pas` — пользовательский SQL для запроса.

Изменения версионируются полями конфигурации (`Конфигурация`, `Версия`, `Кто/Когда/Что изменил`)
и распространяются клиентам из эталонной БД `Стандартная`.

---

## 3. Как запрос выполняется (движок)

Исполнитель — класс **`TbmView`** ([bmView.pas:39](../../c:/bm/bmView.pas)). Цепочка:

1. `View.ViewName := '<имя>'` → загрузка определения из кэшей
   `TbmSchemaViewQueue` (`bmSchemaViewQueue.pas`) и `TbmSchemaViewFieldQueue`
   (классы схемы — `bmSchema.pas`: `TbmSchemaView`, `TbmSchemaViewField`, `TbmSchemaTable`).
2. `View.Open` → `GetSQLText` строит финальный `SELECT` (подставляет дескрипторы
   `^TableName^`, `^KeyFieldName^`, `^Kontora^`, `^Dialog*^`; добавляет `TOP N`, если задан `SelectTop`).
3. SQL выполняется через **`TbmQuery`** (`bmQuery.pas` → `bmQueryLocal.pas`): открывается
   `TADOQuery` на общем соединении `bm`, и **все строки сразу читаются в память**
   (матрица `FRecords: array of array of Variant`).

> ⚠️ При ошибке открытия `TbmQueryLocal.Open` показывает модальное окно и делает **`Halt`**
> (завершает .exe). Поэтому перед `View.Open` для внешнего вызова имя запроса надо
> предварительно проверять (`SELECT COUNT(*) FROM SchemaView WHERE ViewName=…`).

### Headless‑выполнение (без грида)
Уже есть рабочий образец — VBScript‑мост `TbuhtaView` ([bmVBInterface.pas:3640](../../c:/bm/bmVBInterface.pas)):
`TbmView.Create(nil)` (без owner/грида) → `ViewName :=` → `Open` → чтение значений.
Именно этот паттерн использует наш эндпоинт `/query`.

## 4. Как получить результат

После `View.Open` доступно (проверено по `bmView.pas` / `bmQueryLocal.pas`):

- `View.RecordCount`, `View.FieldCount`;
- курсор: `View.First` / `View.Next` / `View.Eof`, `View.RecNo`;
- значения: `View.Values[i]` (Variant, c контролем доступа), `View.ValueByName['Поле']`,
  `View.Strings[i]` (строкой, как в гриде);
- **сырые колонки SELECT** через `View.Query` (это `TbmQuery`):
  `Query.FieldCount`, `Query.FieldName[i]`, `Query.FieldValue[i]` (Variant), `Query.RecordCount`,
  `Query.RecNo := r`.

Для JSON-эндпоинта берём имена и значения из `View.Query` — это «как в выполненном SELECT».

## 5. Пример: запрос `Подразделение`

- `SchemaView`: `ViewName='Подразделение'`, `RootTable='Подразделение'`,
  `SQLJoin/SQLWhere/SQLBefore/SQLAfter` пустые, `Oborot=0`, форма не задана → **запрос без
  джойнов/фильтров/диалогов** (выполняется headless без UI). Алгоритмов нет.
- `SchemaViewField`: прямые поля таблицы — `Номер` (Sort=1), `Название`, `Ключ`,
  `Обособленное подразделение`, `КПП`, `Код ОКАТО`, `ОКВЭД`, `Код ОКТМО`, `ОКПО`, `Код ГНИ`, …
- Таблица `Подразделение` (`SchemaTable`): `KeyFieldName='Ключ'`, `AutoNumFieldName='Номер'`,
  `VidTableName='Вид подразделения'`. Поля: `Ключ` (`Целое`, ReadOnly), `Номер` (`Строка`),
  `Название` (`Строка`), `Вид` (`Ссылка`→`Вид подразделения`), … `_Районный коэф` (`Деньги`).

Это и есть **тестовый запрос** для эндпоинта: ожидаем JSON со списком подразделений той БД,
к которой подключён .exe (проверяется через `/ping`).

## 6. Запуск запроса извне — `POST /query`

См. [c:\bm\bmAutomationServer.pas](../../c:/bm/bmAutomationServer.pas) и
[tools/buhta_client.py](../tools/buhta_client.py).

- Запрос: `POST http://127.0.0.1:8765/query`, тело JSON (cp1251):
  `{"name":"<ViewName>","params":{...},"top":<int>}`.
- Ответ JSON (cp1251):
  `{"ok":true,"count":N,"columns":[{"name","type"}],"rows":[{<поле>:<значение>}, …]}`.
- Типы значений: `null` / целое / число / `true`/`false` / строка‑дата `YYYY-MM-DDThh:nn:ss` / строка.
- Параметры (`params`) передаются в `View.Param`; `top` → `View.SelectTop` (ограничение строк).
- Границы: работает для запросов **без интерактивных диалогов** (период/ID/Zapros/`^Dialog*^`);
  таким запросам параметры нужно передавать в `params`.

### `POST /query/sql` — только сгенерированный SQL (для отладки/правки запросов)

Тело — то же (`name`/`params`/`top`), но запрос **не выполняется**: возвращается SQL,
который движок генерирует для вида. Ответ: `{"ok":true,"sql":"SELECT …"}`.

Реализация: `TbmView.GetSQLText` (тот же генератор, что вызывает `Open`) + подстановка
плейсхолдеров `#STATUS#`→`0 Status`, `#ROOTTABLE#`→`[<RootTable>]` (как делает `Open`,
[bmView.pas:2940](../../c:/bm/bmView.pas)). Поскольку выполнения нет — безопасно даже для
сломанных/тяжёлых запросов. Клиент: `python tools/buhta_client.py "<view>" --sql`.

## 7. Правка запроса средствами программы (add / remove / style)

Запрос можно менять **штатным механизмом редактора** — без перезапуска .exe и с сохранением
аудита. Ключевой класс — `TbmSchemaView` ([bmSchema.pas](../../c:/bm/bmSchema.pas)):
`Create` → `Name :=` → `Load` (грузит дерево полей из кэша) → правка `Fields` →
`Save` (в транзакции `DELETE`+`INSERT` строк, запись аудита `Кто/Когда/Что изменил`,
затем `LoadSchemaView` обновляет кэши и `SendMessage` уведомляет окна — **перезапуск не нужен**).

Эндпоинты (`bmAutomationServer`, тело JSON cp1251):
- `POST /view/field/add` — `{"view","path","caption?","color?","width?"}`. `path` через точку
  (`Начальник подразделения.Фамилия`): сегменты до последнего — цепочка ссылок (поля с
  `ForeignTable<>nil`), последний — лист. Движок сам строит `LEFT OUTER JOIN [<ForeignTable> view]`.
- `POST /view/field/remove` — `{"view","field"}` (по подписи поля). Пустые ссылочные родители подчищаются.
- `POST /view/field/style` — `{"view","field","color?","width?","alignment?","hidden?"}`.

Ответ: `{"ok":true,"view":...,"sql":"<новый сгенерированный SELECT>"}`.

Два правила корректности (учтены в коде): **переиспользовать существующее ref-поле** (иначе дубль
alias джойна) и **перенумеровать `Position` в пре-ордер** после правки (дети идут подряд за родителем,
иначе `Load` соберёт дерево неверно). Цвет — имя (`green`/`red`/…) или число `TColor` (зелёный=32768).

Границы: только виды **без** `SchemaViewAlgoritm` (иначе `Save` их сотрёт — возвращается 409);
правки идут в БД подключённого .exe. Поля поля БД: `SchemaViewField` — родитель `ChildCount=1`
(TableName=исходная таблица) + ребёнок (TableName=внешняя таблица, `Color` = TColor).

Клиент: `python tools/buhta_client.py --add|--remove|--style …` (см. `buhta_client.py`).
