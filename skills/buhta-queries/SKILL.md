# Именованные запросы БУХты (SchemaView) — поиск / выполнение / правка

## Что это
«Запрос» (view) в БУХте — это **именованная запись в `SchemaView`** (корневая таблица + фрагменты
SQL) + её поля в `SchemaViewField` (+ при оборотке — `SchemaViewAlgoritm`). Схема данных хранится
**в самой БД** (таблицы `Schema*`), а не в .exe: программа читает метаданные и на лету строит SELECT.
Исполнитель — класс `TbmView`. **Полное описание схемы, движка и эндпоинтов —
[docs/07-схема-данных-и-запросы.md](../../docs/07-схема-данных-и-запросы.md).**

Выполнение и правка — через HTTP-эндпоинты `/query*` и `/view/field/*` (.exe запущен и авторизован);
поиск запросов — прямым чтением `SchemaView` из БД (`--query-list`, .exe не нужен).

## Рабочий процесс (инструменты tools/)
> Запускай как `python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" …` (полный JSON пишется в `tools\_out.txt`).
```bash
python tools/buhta_client.py --query-list --filter <подстрока>   # НАЙТИ запрос по имени (и/или --root <таблица>)
python tools/buhta_client.py "<имя запроса>" --sql               # показать генерируемый SQL (БЕЗ выполнения)
python tools/buhta_client.py "<имя запроса>" [--top 50]          # ВЫПОЛНИТЬ запрос -> строки в tools\_out.txt
python tools/buhta_client.py "<имя>" -p "дата начала=2025-01-01" -p "ключ=10"   # запрос с параметрами
# --- правка полей запроса (штатным редактором, без перезапуска .exe) ---
python tools/buhta_client.py --add   "<имя>" "Ссылка.Поле" --caption "Заголовок" --color green --width 120
python tools/buhta_client.py --style "<имя>" "Поле" --color red --width 200 [--align 1] [--hidden 1]
python tools/buhta_client.py --remove "<имя>" "Заголовок поля"
```

## Железные правила
1. **Сначала найти, потом работать.** Имя запроса точное и часто с кириллицей/пробелами —
   не выдумывать. `--query-list --filter <часть>` → взять точное `name` из результата. Это
   **первый шаг** любой задачи про запрос (аналог `--form-list`/`--report-list`).
2. **`--sql` безопасен, выполнение — нет.** `"<имя>" --sql` только генерирует SELECT (годится даже для
   сломанных/тяжёлых видов). Само выполнение `"<имя>"` открывает `TbmView.Open`; при неверном имени
   сервер уже проверяет `ViewName` заранее (иначе `Open` делает `Halt` и убивает .exe) — поэтому имя
   бери из `--query-list`, не угадывай.
3. **Ограничивай выборку** `--top N` при разведке — все строки читаются в память.
4. **Правка только через `/view/field/*`** (`--add/--remove/--style`): идёт штатным редактором
   `TbmSchemaView` (транзакция DELETE+INSERT, аудит `Кто/Когда/Что изменил`, `LoadSchemaView`
   обновляет кэш — **перезапуск .exe не нужен**). Не править `SchemaViewField` напрямую UPDATE.
5. **⚠️ Только виды БЕЗ алгоритмов.** Если у вида есть `SchemaViewAlgoritm` (оборотка, `Oborot=1` —
   в `--query-list` помечен `[оборотка]`), `Save` их **сотрёт** → сервер возвращает **409**, правка
   не проходит. Такие виды править только в UI БУХты.
6. **`path` в `--add` — через точку.** Сегменты до последнего — цепочка ссылок (поля с `ForeignTable`),
   последний — лист: `--add "Подразделение" "Начальник подразделения.Фамилия"`. Движок сам строит
   `LEFT OUTER JOIN`. Ref-поле переиспользуется (иначе дубль alias) — это уже учтено в сервере.
7. **Цвет:** имя (`green`/`red`/…) или число `TColor` (зелёный = `32768`). `--align`: 0=слева, 1=справа, 2=центр.

## Рецепт: найти запрос и посмотреть, что он выдаёт
1. `--query-list --filter <часть имени>` → выбрать точное `name` (обрати внимание на `[оборотка]`).
2. `"<name>" --sql` → изучить генерируемый SELECT (джойны/фильтры/вычисляемые поля).
3. `"<name>" --top 20` → фактические строки в `tools\_out.txt` (`columns` + `rows`).
4. Нужны параметры (период/ключ) — передать `-p "имя=значение"` (виды с интерактивными диалогами
   `^Dialog*^` headless не идут — см. docs/07 §6).

## Рецепт: добавить колонку в запрос
1. `--query-list --filter <…>` → точное имя; убедиться, что вид **без** `[оборотка]` (иначе 409, править в UI).
2. `"<имя>" --sql` (запомнить текущий SELECT для сверки).
3. `--add "<имя>" "<путь.через.точку>" --caption "<Заголовок>" [--color …] [--width …]`.
4. В ответе — свежий сгенерированный SQL; проверить `"<имя>" --top 5`, что колонка появилась и заполнена.
5. Откат: `--remove "<имя>" "<Заголовок>"`.

## Модель данных (кратко; полностью — docs/07 §1)
- `SchemaView` (PK `ViewName`) — запросы: `RootTable` (FROM), `SQLJoin/SQLWhere/SQLBefore/SQLAfter`,
  `Oborot` (оборотка → подключается `SchemaViewAlgoritm`), фильтры по конторе.
- `SchemaViewField` (PK `ViewName,TableName,TableField`) — поля SELECT: `Position`, `FieldName` (заголовок),
  `Sort`, `Format`, `Footer`, `Hidden`, `SQLSelect` (вычисляемое выражение), `Color`.
- `SchemaTable` (445) / `SchemaTableField` (7128) — таблицы и их колонки (`DataType`, `ForeignTable`, `ComboItems`).
- Имя запроса **часто, но не всегда** совпадает с именем таблицы (пример: `Подразделение`).

## Когда это НЕ этот скил
- Произвольный SQL к БД (не именованный вид) — `python tools/q.py "SELECT …"` / `exec_sql.py`.
- Печатные шаблоны ([Отчет], FastReport) — скил [buhta-reports](../buhta-reports/SKILL.md).
- Пользовательские формы (dream, ДФМ/скрипт) — скил [buhta-forms](../buhta-forms/SKILL.md).
- Генерация проводок из документов — скил [buhta-genprovodka](../buhta-genprovodka/SKILL.md).

## Завершение
- Кратко отчитаться: какой запрос, что показал/изменил (поле/стиль), как проверено (`--sql` + `--top`),
  как откатить (`--remove`/обратный `--style`). Для вида с алгоритмами — предупредить, что правка только в UI.
