# Генерация проводок из документов (БУХта)

## Что это
БУХта формирует проводки из документов автоматически: по правилам в таблице `[Генерация]` для каждого
вида документа генерируется хранимая процедура `[dbo].[_авто_Документ_<Вид>_генерация]`, которая по
ключу документа пишет строки в `[Проводка]`. Сумма проводки считается одним из ~50 «алгоритмов»
(строковый код в полях `[Сумма]`/`[Сумма руб.]`/`[Сумма USD]`). **Полная карта, структура таблиц и
каталог всех алгоритмов — [docs/11-генерация-проводок.md](../../docs/11-генерация-проводок.md).**
Управление — через HTTP-эндпоинты `/gen/*` (.exe должен быть запущен и авторизован).

## Рабочий процесс (инструменты tools/)
> Запускай как `python "${CLAUDE_PLUGIN_ROOT}/tools/buhta_client.py" …` (туда же пишутся `_out.txt`, `_gen_proc_*.sql`).
```bash
python tools/buhta_client.py --gen-doc-vids                 # виды документов с настройками (+ есть ли процедура)
python tools/buhta_client.py --gen-rules <вид>              # правила генерации вида документа
python tools/buhta_client.py --gen-rule-get <ключ>          # одно правило целиком -> tools\_out.txt
python tools/buhta_client.py --gen-proc-sql <вид>           # генерируемый текст процедуры -> tools\_gen_proc_<вид>.sql
python tools/buhta_client.py --gen-proc-db  <вид>           # текущий текст процедуры из БД -> tools\_gen_proc_<вид>_db.sql
python tools/buhta_client.py --gen-rule-set <ключ> -f "Колонка=значение"   # правка полей правила (+авто-пересоздание процедуры)
python tools/buhta_client.py --gen-proc-refresh <вид>       # пересоздать процедуру (ALTER/CREATE)
python tools/buhta_client.py --gen-proc-recreate <вид>      # DROP+CREATE процедуру (чистое пересоздание)
python tools/buhta_client.py --gen-run <ключ_документа>     # сгенерировать проводки документа (пишет в БД)
python tools/buhta_client.py --gen-provodki <ключ_документа># посмотреть созданные проводки
# найти тестовый документ вида: python tools/buhta_client.py "Документ" ...  или SELECT [Ключ] FROM [Документ] WHERE [Вид]=<вид>
```

## Железные правила
1. **Только тестовая БД.** `--gen-run`/`--gen-rule-set` пишут в БД, `--gen-proc-refresh` — это DDL
   (ALTER/CREATE процедуры). Работать на копии (`NEMP_CLAUDE`), эталон «Стандартная» не трогать.
   Откат при поломке — восстановление копии базы (проверь `--ping` → `db`).
2. **Правка настроек — только через `/gen/rule/set`** (не UPDATE напрямую): он проставляет аудит и
   **пересоздаёт процедуру** вида. Меняет только поля существующего правила; создание/удаление правил —
   не поддерживается (делать в UI БУХты).
3. **Значение типизируется по колонке.** Счёт «10.9» → строкой (varchar), число → как есть; `@null` → SQL NULL.
   Не путать `[Дебет]` (varchar-счёт «60.1») с числовыми полями.
4. **Алгоритмы суммы — фиксированный список** (docs/11 §5); допустимые коды — комбобоксы
   `bmGenEditForm.pas:1142-1308`. Нельзя вписать произвольный код — процедура сгенерируется с
   предупреждением «Недопустимое значение Тип суммы».
5. **Смотри перед правкой:** `--gen-rules` → `--gen-rule-get`, и `--gen-proc-sql` (что будет создано)
   против `--gen-proc-db` (что сейчас в БД).
6. **Новый алгоритм / фикс логики генерации** = правка `bmStoredProcGenDoc.pas` в `c:\bm` →
   **пересборка .exe в IDE Delphi 6** (Project → Build, CLI-сборка падает) → `--gen-proc-refresh`.

## Рецепт: отладка «глюка генерации»
1. `--gen-doc-vids` → найти вид; `--gen-rules <вид>` → правила; `--gen-rule-get <ключ>` → подозрительное правило.
2. `--gen-proc-sql <вид>` → изучить генерируемый SQL суммы/счетов (сверить с docs/11 §5).
3. Найти тестовый документ: `SELECT TOP 5 [Ключ] FROM [Документ] WHERE [Вид]=<вид>` (через `--query`/exec_sql).
4. `--gen-run <ключ>` → `--gen-provodki <ключ>` — увидеть фактический результат (суммы/счета/субконто).
5. Гипотеза в настройке → `--gen-rule-set` (процедура пересоздаётся) → повторить (4), сравнить.
   Гипотеза в коде генератора → правка `bmStoredProcGenDoc.pas` → сборка → `--gen-proc-refresh` → (4).

## Рецепт: проверка нового алгоритма суммы
1. Добавить код алгоритма в диспетчеры `SQLSumma`/`SQLSummaRub`/`SQLSummaUSD` (`bmStoredProcGenDoc.pas`)
   и в комбобоксы/валидацию `bmGenEditForm.pas` → **пересобрать .exe** в IDE.
2. `--gen-rule-set <ключ> -f "Сумма=<новый код>"` (или настроить правило в UI) → авто-пересоздание процедуры.
3. `--gen-proc-sql <вид>` — убедиться, что новый код развернулся в ожидаемый SQL.
4. `--gen-run <ключ>` → `--gen-provodki <ключ>` — проверить сумму в проводке; при необходимости повторить.

### Пример: `Распределение по сумме без НДС` (реализован, вариант A)
Штатная замена костыля (ручное переопределение `@SpecAllSumma_<вид>_<ключ>_One` в `SQLSelect/SQLAfter`, исходно —
правило 1151, вид 29). Числитель = `Сумма − Сумма НДС`, знаменатель и `@Summa` — **с НДС** → проводки не меняются.
Добавлен в 7 точек `bmStoredProcGenDoc.pas` (+ пункт combo и `SetLinkControlVisible` в `bmGenEditForm.pas`); детали —
[docs/11 §5.8](../../docs/11-генерация-проводок.md). Несёт **контроль полноты**: при расхождении суммы разброса сверх
копеечного округления генерация документа падает `RAISERROR`+`RETURN` (переменные `@RaspredCount`/`@RaspredError`).
Проверять регресс-тестом (**PASS**) + негатив-тестом на несходимость (должен упасть с внятным текстом).

## Регрессионный тест (после доработок генератора)
Эталон проводок последних документов каждого вида — `c:\bm\CLAUDE\genprovodka\gen_regress.py`
(`build` один раз, `run` после доработок → PASS/FAIL). Идемпотентность: `/gen/proc/recreate` + чистый
старт (удаление `ГенТип>0` всех тестовых документов) + порядок `(Дата,Ключ)`. Инструкция —
`CLAUDE\genprovodka\README-тест.md`. Гонять `run` после каждой правки `bmStoredProcGenDoc.pas`.

## Завершение
- Проверено: `--gen-proc-db` показывает обновлённую процедуру; `--gen-provodki` — ожидаемые проводки.
- Кратко отчитаться: что изменено (настройка/код), как пересоздана процедура, как проверено на документе, как откатить.
- Смежное: вызов генерации с формы документа — скил [buhta-forms](../buhta-forms/SKILL.md);
  печать проводок/реестров — скил [buhta-reports](../buhta-reports/SKILL.md);
  поиск документов/запросы — [docs/07](../../docs/07-схема-данных-и-запросы.md).
